A helpful assistant that runs on a Telegram interface. Started out as a branch from [[homelabbing|my home labbing project]], Pip emerged as a fun experiment for me to see what n8n is capable of with its AI-first workflow capabilities. Currently, I'm experimenting with Hermes Agent to see what agentic systems are capable of — and the risks they play in it as well. This sounds suspiciously close to [another attempt by another dev](https://anselmlong.com/blog/ava?utm_source=garden.arash.codes&utm_medium=referral&utm_campaign=digital-garden&utm_content=projects-pip) I find cool, but that's just a similarity!

The name Pip sounded cute in my head, and it took me an embarrassingly long time to realise it could also be a play on names with Python's package manager, `pip`. Since Hermes Agent runs internally with Python in its scripting, that's pretty fitting!

# In a previous life...

In its infancy, Pip was essentially an n8n workflow that listened for user messages at its bot DM page. n8n is a workflow tool just like any other — it listens for an input, does a process defined by the user, and ends with an output or closure. Pip isn't any different; its input are either webhooks or listening for a Telegram message, the process an [[agentic-systems|agentic AI system]] powered by tools, and the output a response to the webhooks or a reply on Telegram.

What's fun are the tools that supercharge the agent's abilities to do things. All of them are custom-made for the services and things I use, so they seem *somewhat* arbitrary but very personally useful. These tools include:

- Web search + knowledge gathering with SearXNG + Wikipedia tools
- Home lab management tools including Tailscale and command execution tools
- A Strava tool to tap into runs and other fitness activities (lol)
- A bookmarks tool to tap into saved links (Readeck)
- A calendar tool to fetch events from my calendars
- An LLM costs tool that aggregates the accrued costs from API calls

The model Pip uses is hot-swappable thanks to the Chat Model nodes n8n offers. Pip is currently using Anthropic's Claude 4.5 Haiku — for some reason, I prefer the responses generated by this model than other competing [[large-language-models|LLMs]].

# Overview

Pip is currently being controlled by an instance of [Hermes Agent](https://hermes-agent.nousresearch.com/) running on one of my home lab devices. Thanks to the vast development and priority on user experience, it's been quite easy to set things up and watch things unfold!

Hermes Agent supports hot-swapping different LLMs per-message and per-session. Currently, in my own experiments, I've since played around with the following models to observe their usage and cost impacts:

- Anthropic's Claude 5.5 Haiku
- OpenAI's GPT-6 Luna
- LiquidAI's LFM3-1.7B (run locally using Ollama)
- NVIDIA's Nemotron 3.5 Bolt (run locally using Ollama)

Since I currently lack a strong device in my home lab that can sufficiently support running stronger open frontier models, I'm currently bound to using API calls to frontier providers for Pip to function well.

Some particular goals that I'm looking to accomplish with this experiment is seeing:

- The capabilities of agentic systems now, especially when paired with different models that have their own subtle "personalities" — ways they approach tasks and how they respond back to me.
	- Whether agentic systems are capable of handling medium-scale personal challenges that may be approachable with code, through solid reasoning and self-recovery upon encountering issues or errors.
- The feasibility of using an agentic system now, both in terms of financial (API tokens cost money!) and temporal (having to learn and be patient in correcting issues) resources.

# Devlog

**7 November 2026**

- I started this project a couple of days ago when I had the time to, and it's been my obsession ever since. Hermes Agents makes it pretty easy to fall for the excitement of getting everything set up, but I must be cautious of the implications of exposing real files not only to models that can make irrecoverable changes to them, but also the providers behind them who may log and store snippets of prompt history.
- Hermes Agent's ability to self-learn skills is pretty remarkable, and I think this is a strong unique selling point to truly making it an agentic system that can run on its own. YMMV though, since Hermes Agent's only as strong as the LLM connected to it; LFM3-1.7B was surprisingly solid, but is still as bad as any sub-30 billion parameter model can do.
- I've cautiously added connections to the most sensitive of my development tools and its stack, including GitHub, Cloudflare, Vercel, and even Komodo (the web interface for managing Docker containers — the services running on my home lab). Whether by my own paranoia or something the harness cared to remember, Pip also seems to share a similar trait of being overly cautious before performing something. Like father, like son, I guess?
- I've run an experiment where I got Pip to perform most of the process of adding a new service to my home lab — namely, to create an appropriate Docker Compose file in the home lab repo, create a new Stack on Komodo, then configure it properly to launch and deploy it.
	- Pip stopped at certain important points which, to me, felt like adequate stopping points for the human in the loop to continue: configuring the Stack in Komodo with environment variables and before pushing the newly-created Compose file to GitHub (granted, this is more of a technical limitation with `pinentry` being GUI-based and interactive), etc.
	- I'm surprised that Pip learnt my caution to limit exposure of sensitive information to the prompt history itself so that the LLM provider doesn't receive as much; or, honestly, it could just be Pip saying this to me for assurance while sending entire file contents to the provider anyway — the likelihood of entire file contents being leaked through tool uses is pretty high.
